# Designer guide

`cases.json` contains the campaign. Each case has a name, named patient and one-line life, diagnosis, surgeon, timer in seconds, par score, outcome sentence and ordered `phases`. A phase has a name, a single current objective, an urgent callout, a `plate`, optional `strain`, optional scripted `code` shock count, and `hazards`. JSON parse errors name the file, line and column.

Hazards use `kind`, `pos: [x,z]`, optionally `end: [x,z]`, `hidden: true` and `stage`. Gameplay bounds are x −9…9, z −4…4.1. Keep targets around x −5…5, z −2…2 for generous HUD clearance. `end` is the incision/seam endpoint, forceps pull axis or bone's snap destination. `stage` advances a tumor, nodule, ember or bone's tool sequence; omit it to start at zero.

Kinds: `incision`, `laceration`, `bleeder`, `pool`, `hook`, `shard`, `polyp`, `tumor`, `burn`, `inflammation`, `bone`, `nodule`, `sac`, `ember`, `tether`, `soloist`, `tendril`, `dressing`. Their tools, drain, progress, gesture and misuse rules are in `Hazard::tool` and `Surgery::operate`. A phase advances only when every task is cleared and scripted shocks are complete. A pool reveals hidden objects below it when suctioned. Scanner reveals hidden objects for eight seconds. Completed seams retain visible stitches. Every phase is a retry checkpoint.

Plate keys: `forearm`, `abdomen`, `bowel`, `chest`, `lung`, `liver`, `femur`, `pericardium`, `heart`; Code Blue reuses the forearm field. Plates are procedural in `pav_view/src/surgery.rs`; extend `height` and `color_plate` for new organs. Strain keys: `introit`, `lacrimosa`, `dies`, `furnace`, `libera`. They enable beat-driven movement, bursting sacs, fever and heat rings. Use consecutive phases for shell divisions, eye windows, furnace reveals or the Soloist. Core coverage records each phase, tool, strain, hazard and gift.

Story authoring source: the product directory's `tools/make_story.py`. Each line is `Speaker|Dialogue`; scenes name the set and two actors. Run that script to regenerate `web/story.json`, or edit JSON directly (then do not regenerate). Each JSON line has `who`, `text`, `expr`, `left`, `right`, `set`. Speakers are Mara, Pet, Bashir, Teddy, Voss, Vane. Expressions: neutral, alarmed, stern, soft. Sets: corridor, gallery, gala, ward, depot, scrub, recovery, ship. Actor silhouettes, colours, expressions and procedural animation are in `pav_view/src/surgery.rs::actor` and `theatre`. Music, cues and voice timbres are in `web/audio.js`.

Tuning: all live variables are in `Tune` in core `surgery/mod.rs`. Pause → Dev mode changes them immediately, can keep the simulation Live, or let the Bot operate. Reset All restores constructor defaults. Each dev slider shows its default. Use the case/phase page to jump, then save a snapshot before testing a hazard. The browser embeds content; rebuild with `tools/build.sh` after editing case data or Rust. Repack with `tools/bundle.py` after story or shell edits. Native `pav load scene=surgery/case/3` reads cases from disk at load, so no Rust rebuild is needed for data-only tuning. `pav play scene=surgery/campaign bot=true seeds=10` plays the complete campaign. Build the native CLI with `cargo build --locked -p pav_tools --bin pav` from the engine directory.

Run `python3 tests/run_all.py --rust` from the product directory to check content, tools, scores, all cases, the campaign, survival, snapshots and replays. The same command with no flags adds browser and hub checks. Calibrate `par` from the expert bot's measured score, then adjust timer and drain for human pacing. To add a new gesture or strain, update its bot planner too; campaign coverage should prove it can be completed.
