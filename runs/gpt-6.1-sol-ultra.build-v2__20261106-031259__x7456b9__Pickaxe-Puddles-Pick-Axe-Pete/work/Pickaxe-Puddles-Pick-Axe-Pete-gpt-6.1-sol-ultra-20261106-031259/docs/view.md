# Native presentation and asset authoring

Load `src/view/assets.js` after the full native engine and before `src/view/view.js`. `PP.View(game)` provides `update(dt, sim, settings)`, `draw(renderer, sim, settings, {debug})`, `reset()` and `dispose()`.

The renderer reads authoritative state only. It never changes positions, action timers, tool wear, health, pickups, score or progression. Cosmetic event IDs are deduplicated separately. Cosmetic dust and geometric variation use a separate deterministic hash and cannot consume gameplay RNG.

The side-view camera fits x=0..576 and all five/six/seven native tiers on TV and landscape displays; native z remains up and y remains depth. Each platform's drawn top is exactly its collision floor.z, with the same gap intervals. The camera leaves safe space for the HTML HUD and controls. Portrait uses 1.75× horizontal tracking of `view.localId` (first active miner by default), preserving every vertical tier and enlarging the miner to about 32 physical pixels on a 390×844 phone. Horizontal edge arrows give advance warning for incoming doors/ore and directions to offscreen keys, needed picks and fallen partners. A short lookahead follows run velocity; reduced motion removes eased camera lag. Authoritative HUD text stays outside the pixel scene.

`assets.js` registers original native materials and shapes: gate/pistons/lock, extraction winding gear, normal gold ore, cyan spurred bouncing ore, banded heavy ore and replacement-pick stand. Ordinary crate, barrel and cart props use the engine library. The miner registers native lamp helmet hooks, a second twin-lamp silhouette, the substantial animated pickaxe weapon and held boast/break/jam/rescue/redirect poses. Rig motion builds on Humanoid, Platformer.rigState and native Attack phase state.

Animation mapping covers breathing/boast, run, jump rise/apex/fall, soft landing, climb/dismount, duck, attack anticipation/contact/recovery, high/low redirect cue, final-contact wear marker, tool break/unarmed reaction, collect/cheer, jam, unlock transition, hurt, down, rescue, extraction gears and victory. Drawing poses does not create hits. Reduced motion freezes dust drift and gear rotation, removes smears/rings and door shutter motion; reduced flashes suppress flashing temporary rungs, last-chance flicker, hurt flash and repeated rock highlights. Both settings preserve shape/text cues.

Open `src/view/preview.html` by file URL for a native room/gear/rig preview. It shows the seven-tier climax, all three ore silhouettes, both miners, a rising key, falling pick and all gate symbols. `preview-check.py` launches installed headless Chromium, checks native/page errors and captures the preview at 1920×1080; it is an authoring aid rather than completion proof. No downloaded visual assets, raster generation or audio files are used.

The first preview caught an actor-coordinate error: native r.actor callbacks must use supplied ox/oy because drawing occurs on an actor buffer. Using r.w inside that callback clipped rocks. The callback was corrected and the ore silhouettes are now visible. This was a major visual defect, not a progression blocker in the underlying simulation. The preview ran file:// without page/native errors after the fix.

## Integrated release visual proof

The bundled file launched from file:// at 1920×1080, 390×844 touch portrait and 844×390 touch landscape without native/page errors. Captures in `evidence/integrated-*.png` cover title, opening, dense Motherlode, unarmed state, pause, Developer and About screens. `portrait-warning.png` shows an offscreen rising-key arrow together with a MOON incoming warning; `portrait-tracking.png` shows the miner after moving to x375.9 and the camera tracking the miner at screen x478.7 of logical width960. `reduced-flashes.png` confirms the quieter presentation; programmatic inspection with reduced motion/flashes and shake0 observed native shaking0. TV and landscape retain whole-room composition. These screenshots judge layout and silhouettes, not physical TV comfort or real touchscreen feel.

The native engine fixed-resolution screen initially clamped scale to at least1, which cropped a 960px game buffer on a390px screen. The reviewed engine patch allows fractional scaling below1. Portrait proof now measures S0.40625, OX0, W960/H2078; landscape measures S0.5416667, OX−1, W1559/H720. The −1px rounding margin is harmless. This mandatory touch-mode cropping was a critical product defect. Dependencies documentation records the exact engine patch.
