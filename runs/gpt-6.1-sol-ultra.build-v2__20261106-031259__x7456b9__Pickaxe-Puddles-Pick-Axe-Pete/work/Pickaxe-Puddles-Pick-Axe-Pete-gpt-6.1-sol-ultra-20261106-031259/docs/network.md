# Shared-world networking

`PP.Net` is an authority/client adapter over the pristine Session Protocol v1 client. Construct it with `createSim({seed,seats,online})`, `onState(sim)` and `onStatus(status,detail)`, then await `connect()`. A false result selects standalone flow. A true result has already installed lifecycle handlers, built the mine, and called `AIHub.ready()` once without an audio gesture.

Hub player IDs are **zero based** and are used unchanged as miner IDs. A hidden nonplayer authority has `server === true` and `localId === null`; it starts its own 120 Hz fixed-step scheduler and does not need an engine Game, camera, input device, renderer or AudioContext. Visible copies call `tick(dt,localIntent)` from their engine's fixed tick. Never call `sim.step` elsewhere for an active network authority.

A visible player-host temporarily hands stepping to a separate fixed-tick timer when its document becomes hidden. That timer supplies neutral local input while continuing to authenticate and apply remote input; residual renderer ticks are ignored while it owns the clock. Its 1.25-second catch-up bound accommodates ordinary one-second background timer batching, and it clips elapsed time at the Hub countdown boundary. On return to visibility, the timer stops and `onClockHandoff(false)` lets the application restart the existing engine loop with a fresh RAF timestamp, avoiding duplicate catch-up. `onClockHandoff(true)` reports the initial handoff. Finish, end and disposal remove the listener and timer. Replicas, standalone games and the nonplayer server retain their existing ownership. Hub still owns its 20-second hidden-host void rule; JavaScript cannot progress during complete operating-system suspension.

Only the host steps authoritative state. Clients send canonical held actions plus monotonically increasing Jump/Redirect/Interact edge counters, sequence number and run/chamber epoch. Packet loss cannot discard an action edge permanently because subsequent input packets repeat the counters. The host authenticates the callback sender, ignores stale epochs/sequences, consumes each edge once and neutralizes held controls after 700 ms of silence. Each room epoch starts fresh edge baselines on both ends; per-entry epoch markers preserve a genuine first-new-room edge even if it arrives before the host's next step observes the chamber change. Old queued or unacknowledged edges cannot replay into the next chamber. A client menu therefore sends neutral input while the shared world and Hub deadline continue.

The host sends reliable full-state keyframes twice a second, with stable event IDs and input acknowledgments, and compact unreliable positions at most eight times a second. Position messages stay below approximately 1,200 bytes. Large keyframes are chunked, bounded, and assembled atomically. A single queue and 78 ms send gate cap combined output to at most 13 messages/s, below Hub's 20/s limit. JSON messages are checked below 16 KB. The client restores complete native simulation objects only from keyframes; between them it interpolates other actors. A separate native Platformer clone predicts only the local miner's traversal immediately. Timestamped keyframes reconcile that clone and replay recent local traversal inputs; it never applies attacks, damage, pickups, score or transitions. The replica never calls `Sim.step`. Very distant/overflowing rock positions wait for the next keyframe rather than inflating an unreliable datagram. Final chunked keyframes drain through the same bounded scheduler before the once-only finish report, within the Hub grace interval.

`diagnostics()` exposes sent/received/rejected/dropped counts, largest message, maximum rolling send rate, snapshots, queued traffic, active epoch, runtime role, local ID and unacknowledged counters. There is no external socket, custom name, chat or emote channel.

Nonhost departures remove the miner through `sim.removeMiner`, which owns key recovery and solo viability. Extraction, wipe and wall-clock time-up finish once, from the host, with all remaining players in one tied standing and a team `won` value. `AIHub.time()` and `limitMs` enforce the deadline independently of simulation speed and local menus. End removes listeners, clears held input/queues/interpolation, and stops the owned server timer; the application end callback must stop its own audio and input polling too. Host loss is left to Hub's void-round policy.

Status values are `waiting`, `countdown`, `play`, `finishing`, and `end`; `time-up` is also reported to the callback with its grace detail. The adapter uses the standard Hub instruction card and does not answer or replace that card.

## Verification entry points

- `tests/hub-unit.mjs` exports `runHubUnit()` → 15 quiet checks: lifecycle/countdown, authentication/epochs/sequences, repeated action edges, chamber-edge baselines and the fast-new-epoch race, silence, leave, bounded traffic, time-up, wipe, hidden authority, native snapshot trust, atomic final-state draining, and visible-host visibility handoff. Visibility regressions cover progress with no RAF, neutral host/live partner input, no double stepping, 120 ticks per batched second, countdown clipping, foreground callback, teardown on finish/end/dispose and unchanged other runtime roles.
- `tests/hub-native.mjs` exports `runHubNative()` → 12 checks with two real native mine simulations under 150 ms latency, 50 ms jitter and 5% unreliable loss. Confirms immediate local traversal prediction, authoritative remote movement/Jump, no replica simulation stepping, native restores, traffic bounds and key-carrier departure recovery.
- `tests/hub-expedition.mjs` exports `runHubExpedition({route,server,seed})` → a result containing `count`, explicit simulation seed, seconds, score, loss count, actual per-chamber geometry/patterns, feature counts and event types. Each ordinary case contributes 13 checks; the hidden authority case contributes 14. All three route choices completed with ordinary canonical pilot inputs and no grants, teleports, invulnerability, developer or attract flags. The current authored route variants are included: SUN preserves the base arrangements; MOON mirrors gaps and favors bouncing ore; STAR staggers gaps and favors heavy ore. Ordered chamber entries, three keyed unlocks, extraction wave changes, actual break/replacement, ore collisions, unique event IDs and genuine timed contacts using **both high and low redirects** are asserted. This scripted competence is faster than a first human expedition; it is a progression proof, not evidence of first-player pacing or controller comfort.
- `tools/hub-check.mjs` exports `runHubChecks()` → the passing check count from the unchanged official checker plus packaging checks. It verifies the game served by its owned origin, the pristine first client script, correct 15-minute/how-to tags, and a stable HTML hash, then exercises one and two seats, faulty-network play, host loss and nonplayer authority. Its evidence is `evidence/hub-report.json`; a changed HTML invalidates the run. The unchanged official checker itself waits for `document.body.dataset.complete === 'true'` and requires `window.__hubCheck.pass === true`.

During network-specific verification, the first hidden-server accumulator test exposed a floating-point boundary that omitted one tick at exactly half a second; the scheduler now uses a small comparison epsilon. Contract review found and corrected unsupported metadata names (`session-duration` and `session-how`) before release; the wrapper now enforces the actual `session-minutes` and `session-howto` fields. A later epoch audit found that unacknowledged old-room action counters could replay in the next room, while a sufficiently fast new-room packet could instead be cleared by the host's next epoch reset; explicit fresh baselines and per-entry epoch markers fix that defect, with a regression case covering both directions. An early expedition assertion used an incorrect test-side event name (`key` rather than `keyCollect`); that was a test assumption, not a game defect.

Lifecycle audit D25 found that `autoPause:false` does not keep browser RAF running in a hidden player-host tab. A read-only reproduction advanced the Hub clock five seconds with no RAF while the mine remained at one tick and had no independent timer. The visible-host timer handoff fixes that mandatory-mode freeze without introducing a second stepping owner. Its deterministic visibility regression proves continued remote gameplay and full cleanup.
