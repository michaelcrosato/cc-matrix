TAILFOX 64 - THE LANTERN WING
An original spiritual successor to Starfox 64 (N64). Single-file HTML demo.

SOURCE INFORMATION
- Date: 2026-10-20 14:26
- Source: Starfox 64 for N64
- Game title: Tailfox 64 (picked at random by code from 50 brainstormed riffs on the source name)
- Tech: Three.js 0.160.0 (WebGL) loaded from the jsDelivr CDN together with its EffectComposer, RenderPass, UnrealBloomPass and OutputPass addons; hand-written vanilla JavaScript (ES module, modules bundled into one HTML file by a small Python script); Web Audio API for all sound and music (procedural synth and 16th-note sequencer); Gamepad API (PS5 DualSense, standard mapping, dual-rumble); localStorage for settings. No other engine or library.
- Art Direction: Low-poly, flat-shaded N64-inspired look with modern lighting: sun shadow maps, fog, vertex-colored procedural terrain, additive particle explosions, bloom glow, canvas-drawn comm portraits and a large-type 10-foot DOM HUD and menu system.
- Animation: Fully procedural and code-driven (no keyframed assets): rail-relative enemy path functions, steering behaviours for all-range dogfights, damped camera and ship motion, tweened UI, typewriter comm text and a pooled GPU point-sprite particle system.
- Testing: The prompt said to write no tests and do no tests, because testing is done separately. The game was not run or played by the author. The only check performed was a JavaScript syntax parse of the bundled script at build time.
- Environment: Claude Code CLI (headless); Linux; browser unknown
- Model: Anthropic, claude-sonnet-5-5, reasoning effort medium
- Usage: unknown (no cost, token or session-time telemetry was available to the model)

ENGINE FEEDBACK
There is no game engine in the usual sense here. The "engine" is Three.js plus the browser platform APIs.
- What did you like most about the engine? Three.js gets a convincing N64-meets-modern look from very little code: flat-shaded standard materials, a shadow-casting sun, fog and a bloom composer. A single CDN import also makes one-file sharing easy.
- Did you get stuck or guess wrong? I could not run anything, so every API detail was reasoned rather than verified (Object3D.lookAt facing +Z, Euler order for flight attitude, shadow-camera projection needing an explicit update, particle shader attributes, audio autoplay rules when only a gamepad is used). I caught a few of these in review; others may still be wrong.
- What was the most important thing you had to build yourself? The whole gameplay layer: a rail-relative enemy director and level script, free-flight all-range mode, charge and lock-on shooting, boss state machines, collisions, a procedural audio sequencer, the controller-first menu and HUD system, and the attract-mode pilot.
- What was the hardest part about using the engine? Three.js has no entity, collision, input, UI or audio layer, so all of that is hand-rolled. Keeping many modules coherent in one shared scope without being able to execute them was the real difficulty.
- If you had to remove or overhaul one thing from engine, what would that be? The split between the core build and the examples/jsm addons, which forces import maps and exact CDN version paths for something as basic as post-processing.
- If you could change one thing about the engine, what would it be? A small built-in gameplay layer (entities, pooling, simple collision queries, input mapping) so a vertical slice does not start from a blank page.
