# Release verification

From the development folder, run **`node tools/verify.mjs`** (also `npm test`). Success prints only one count line. Failures print their case/context and that count. The runner rebuilds the exact root HTML, checks provenance/schema/embedded-script syntax, then runs native simulation, fake-Hub protocol/gameplay, file-browser input/audio and the unchanged official Hub harness. It captures successful child output. All browsers and the OS-selected loopback server are owned by these scripts and closed in `finally`; no shared ports or unrelated processes are touched.

The final result and SHA-256 of the tested artifact are written to `docs/evidence/verification.json`. `index.html` is generated byte-for-byte from the same bundle as the root deliverable. Feedback comes from one data model, `docs/feedback.json`, embedded into About and written to the root exit-interview.json.

## Defects

`issues.json` records **23 unique fixed product issues**, including **9 critical** issues. Critical means an issue prevented launch, a required control/progression path or a mandatory mode, or lost authoritative ownership/state. Counts include automated tests, native raster/phone inspections and explicitly labelled integration review findings. Test-author mistakes (locator naming, glyph cycle assumptions, partial-touch event semantics and an accidentally disabled test spawn director) are excluded. Repeated failing assertions for one root cause count once.

The longer online run was useful precisely because the official short harness already passed: actual client traversal needed prompt owner prediction, and action-edge direction needed reliable context. A separate reactive-Pilot limitation was also corrected using visible warnings and ordinary controls; that controller limitation is not counted as a new product defect. No god mode, teleports, health/resource grants or completion switches are used in full expedition evidence.

Actual canvas rendering is covered in the independent file-browser/full-expedition suite and visual captures. A legal AI-team wipe in an earlier painted run was correctly reported as a loss; no health, supplies, simulation rules, tick rate or completion assertions were relaxed.
