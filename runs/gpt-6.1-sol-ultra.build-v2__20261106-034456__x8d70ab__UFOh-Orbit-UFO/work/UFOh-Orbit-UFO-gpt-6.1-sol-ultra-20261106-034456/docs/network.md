# Shared-world networking

UFOh Orbit uses AI Hub Session Protocol v1 with the exact, unmodified released client 1.4.0 at revision `35a1047f2067b2af3de3943f0fe452f39105d869`. The client is the first script after the charset in the delivered HTML. `HubAdapter.connect()` calls `AIHub.connect({mode:'shared-world',seats:[1,2]})`, constructs the mission from the Hub seed, installs lifecycle handlers, and calls `ready()` once without a user gesture. A null connection chooses standalone. Session play skips the independent title, records and initials screens.

Only the authority calls the simulation. Its pilot array follows the Hub roster with stable indices. A dedicated server host has `localIndex=-1`; no phantom pilot is inserted. The same mission simulation runs, readies, sends snapshots and reports results without local input. Clock advancement and combat wait for the start event and `AIHub.time()>=0`.

Nonhosts send sequenced movement, aim and fire intent at 10 Hz, including neutral heartbeats. A one-tick fire press is latched until a packet is successfully sent, then consumed; opening an overlay or ending the round discards an unsent press. This preserves quick taps without introducing a second fire event or extra packets. The host accepts intent only from current roster members, rejects old sequences, clamps numeric input, normalizes steering and expires held input after 0.5 seconds. A local overlay sends neutral intent while the world keeps running. The Create+Options reserved chord is handled by the controls layer.

The authority targets eight complete snapshots per second using reliable Hub delivery. Repeated actor dictionaries are packed as shared-key tables, floats are rounded to three decimals, and simulation-only content, replay and historical counters are omitted. Every gameplay actor and projectile is transmitted. Last 24 simulation events support local audio and visual cues; particles stay local. A snapshot includes the latest accepted sequence for each pilot. A very large snapshot is fragmented into bounded messages and assembled atomically; the previous complete state remains visible until all fragments arrive. Congestion lowers complete-snapshot frequency instead of deleting actors. The adapter sends at most 16 messages in any one-second window, reserving capacity below the client's 20/sec limit. Every message is measured in encoded bytes and stays below 16 KiB. Unicode is included in size calculations.

Nonhosts only accept world data from the current `AIHub.host`. Remote actors interpolate between the two latest authority frames. The local pilot predicts bounded movement and clockwise bead motion, reconciles toward the authority, and retains an exposed ring while fire is unacknowledged. Damage, collisions, score, fusion and encounter completion remain authority decisions. Predicted presentation is discarded when a new snapshot arrives.

A departing nonhost is marked departed/down by the authority, its intent is cleared, and later packets are rejected. Remaining pilots continue; no host migration is attempted. Host departure is voided by the Hub. On victory, defeat or time-up, a reliable final snapshot is queued before exactly one `finish({standings:[remainingIds],scores,won})`. Time-up makes an unfinished mission a loss with its earned team score. Every remaining player ties. `end` clears queued traffic and local input; the game stops sound and leaves navigation to the Hub.

No extra sockets, matchmaking service, chat, names, dialogs or navigation are introduced. Hub names are rendered as text. Standalone couch co-op shares one simulation and does not open a network service.

## Verification

`tests/hub.mjs` exports `runHubTests()` for the single test coordinator. Its 22 checks include quick-fire sampling, exactly-once tap acceptance, overlay/end cancellation, send retry, automatic readiness, countdown gating, intent/membership/sequence validation, stale input, bidirectional neutral heartbeats, server authority, departure, time-up/final ordering, single finish, end silence, dense complete snapshots, Unicode size bounds and conservative predicted shield state.

`tests/hub-browser.py` runs the original conformance harness against the actual generated HTML using a temporary localhost server bound to `127.0.0.1` on an OS-selected port. The server and browser are owned and closed by the script. Results and detailed failure evidence are written under `artifacts/`; normal stdout contains only its machine-readable summary for the coordinator. Cases include two players, 150 ms latency/50 ms jitter/5% loss, host departure, server hosting and the supported one-player path. The browser test also observes different viewport sizes and a resize through the authority debug API.

Remaining limitations: browser emulation establishes the tested protocol and authority behavior, not real internet routing or subjective feel on physical controllers. Reliable Hub transport is the baseline; the game does not claim an independent unreliable transport.
