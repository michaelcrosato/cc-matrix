# Hub integration and observed evidence

The final artifact embeds released AI Hub protocol 1/client 1.4.0 verbatim as the first script immediately after charset. Current upstream revision is `35a1047f2067b2af3de3943f0fe452f39105d869`, matching PLAN.md. `scripts/build.mjs` declares exactly two players, shared-world, a three-minute declaration and controls/goal with the documented `hub:session-*` keys. There is no standalone matchmaking service or room browser.

`src/online.js` checks `AIHub.active` before connecting, registers lifecycle handlers before calling `ready()` automatically and uses the default Hub card. The host alone advances the production simulation at 120 Hz, targeting the current synchronized `AIHub.time()` after converting milliseconds to seconds once. Combat remains still while the clock is negative. A dedicated server has `seat:null`; neither the simulation nor adapter requires local input, audio or a camera. Root calls the adapter while local settings/pause overlays are open.

Every remote intention carries a monotonically increasing sequence and the measured Hub-clock timestamp. Seat authority comes exclusively from the authenticated message sender. Ordinary releases carry local held duration to preserve the timing skill under transport delay. The host matches a release to a corresponding accepted begin, checks its local timestamp is within 650 ms, checks measured hold versus begin/release timestamps within 80 ms, excludes time overlapping authoritative reload/recovery, and bounds transport tolerance to 120–400 ms. Production simulation imposes its own additional 220 ms clamp and clamps power to the legal curve. No client-reported collision, damage, score or arbitrary power is accepted. A safe cancel remains legal even if delayed; a stale release clears the charge without firing.

Host snapshots run at approximately 6.25 Hz. They contain the complete current block-health bit string, players and projectile tuples, so a lost unreliable state packet cannot leave a permanently different castle. Only the host's state is applied, and snapshots with a stale sequence or incomplete baseline version are ignored. The reliable baseline identifies the validated court/seed/config and regenerates the same static geometry, followed by full dynamic state. It repeats every four seconds; all clients acknowledge baselines and applied sequences even if they never press Fire. Reliable launch/impact/collapse/recovery/outcome events are coalesced into a bounded event packet. A local token bucket reserves capacity for cancel/release/final state and stays below Hub's aggregate 20-message/sec refill and 40-message burst; `send() === false` retains an ordered bounded retry. JSON serialization and 16KB size validation happen before queueing.

On time-up, remaining authored castle-health fraction is compared, followed by direct-hit score and a transparent draw. The host publishes final reliable state, waits for passive-client acknowledgements or a two-second fallback, and calls `finish()` exactly once within Hub grace. Standings contain Hub player IDs grouped by ties. Player departure causes an authoritative forfeit. Host departure is voided by the Hub, with no invented migration. On `end`, queued traffic and all input/audio stop immediately. Standalone restart, tour load, quit-to-title and developer world mutation routes are disabled in the session UI and runtime.

## Verification commands

`node tests/hub-unit.mjs` exercises injected transport with the real production simulation and adapter, including 150 ms latency, 50 ms asymmetric jitter, 5% unreliable loss, rejected-send retry, passive ACK, sequence deduplication, measured-hold power, final state, dedicated server and departure/end paths. It prints only failures and an assertion count. `runHubUnit()` is exported for the aggregate verifier.

`/home/micha/.local/share/pipx/venvs/playwright/bin/python tests/hub-browser.py <final HTML path>` copies the exact final artifact bytes to project-owned staging and runs the acquired, unchanged official harness/bridge/round modules on an OS-selected loopback HTTP port. It requires both `document.body.dataset.complete === 'true'` and `window.__hubCheck.pass === true` for normal, adverse-network, host-leave and dedicated-server cases. A separate two-page scenario holds and releases Fire on both seats and checks real projectile creation, destruction convergence and no post-end traffic. The server and browser are closed by the runner. Detailed observed reports are saved under `artifacts/hub-browser.json`.

Physical controllers, remote human opponents and real internet transport are unavailable here. These tests use two or three browser frames and the official simulated transport, plus the deterministic injected transport. They are not claims of real-device or WAN testing.

## Observed integration findings

- The first four official harness scenarios passed, 80 observed assertions including the official `__hubCheck.pass` gate and artifact/packet checks. Initial active-Fire integration found an unrequested remote pause overlay: default-card focus loss during negative Hub time had opened pause before play. The input adapter was corrected to clear input but ignore prestart Hub blur. The affected Fire scenario then passed 6 assertions, including both authenticated seats firing, state convergence and stopped post-end traffic.
- A code audit followed by a production-simulation regression reproduced a critical recovery lockout: the host's pending network begin record survived a crew interruption even though production held/charge/buffer state had cleared. Two assertions failed before the fix. The adapter now retires such begin records after authoritative stepping. The full headless online suite passes 39 assertions, including a real predicted crew shot, interruption, recovery and a fresh legal throw.
- The delivered build uses the correct documented `hub:session`/`hub:session-minutes`/goal/howto metadata. Earlier guessed metadata keys were corrected during contract review before official verification.
- Actual official-harness host traffic reached 587 bytes for a reliable baseline, 320–321 bytes for passive-state snapshots, 6–7 messages in a one-second window and queue peak 1. The active-Fire case reached 363-byte snapshots and 84-byte intention packets. No actual browser send rejection occurred; injected headless rejection exercised retry behavior. One finish call occurred per normal/adverse/server host.
- A further final rerun was intentionally stopped when the root integrator requested browser ownership for aggregate verification. The aggregate verifier is responsible for the final artifact's combined report; stopped runs are not counted as passes.
