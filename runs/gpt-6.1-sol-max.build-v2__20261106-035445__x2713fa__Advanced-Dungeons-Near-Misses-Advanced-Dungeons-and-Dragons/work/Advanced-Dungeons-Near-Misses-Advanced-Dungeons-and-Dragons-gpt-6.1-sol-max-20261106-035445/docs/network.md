# Multiplayer transport and verification

The sole authority runs the production simulation in all modes. Seats are 1 and 2; a Hub server owns no seat. A regular host controls seat 1 and a direct guest controls seat 2. Hub player IDs map to their roster order. Host-local input enters the same command callback without a network hop. A guest can request movement and discrete actions; only the authority awards ammunition, hits, progression and results.

`NM.Network` implements the contract in `contracts.md`. In online play, call `sendInput` for the local seat and `update` from every fixed update, including while an overlay is open. An open overlay submits neutral input. For a managed Hub round, step the authority only while `running` is true. `start` prepares seats before readiness; it is not permission to move ahead of the shared start clock. Call `finish(win,stats)` when the authority resolves an outcome. `finish` is idempotent. Local simulation/storage is root-owned and separate from managed sessions.

Packets carry protocol 1, content revision `near-misses-1` and a session nonce. Dynamic snapshots use browser-native DEFLATE when available and otherwise JSON. Full state is bounded to 600 KB before compression; compressed packets are bounded to 15,000 UTF-8 bytes and reliably chunked if necessary. A receiver applies a fully reconstructed snapshot atomically, in sequence. Static geometry is never sent. One reliable ordered WebRTC channel carries snapshots, commands and handshake; this intentionally favors correctness over a second low-latency channel. Hub sends also use its reliable channel. Authority snapshots target 8 Hz. Guest held-input packets target 15 Hz. A rolling 18-message/second queue includes all startup/handshake/chunk sends and coalesces unsent states. Each discrete action retains its monotonic ID until acknowledged in state, and the authority rejects duplicate or stale IDs. Neutral held input replaces a missing peer heartbeat after 0.65 seconds.

Direct pairing has no discovery service or invented room codes. Both players load the same game release. Host exports a complete offer, guest imports it and exports an answer, then host imports that answer. Codes expire after 30 minutes and are nonce-bound, role-checked and version-checked. Candidate gathering has an 18-second timeout. Default discovery uses the public `stun:stun.l.google.com:19302`; there are no private credentials. `host({lan:true})` deliberately omits STUN for local-network pairing and tests. Some NAT/firewall combinations need a TURN relay; no universal WAN claim is made. A disconnected authority ends the connection; no migration is invented. A host retains its save and removes a departed guest.

Hub client 1.4.0, Session Protocol 1, pinned commit `35a1047f2067b2af3de3943f0fe452f39105d869`, is unchanged and must be the first script immediately after charset. All Hub listeners precede `ready()`, which is called exactly once without a gesture. The common clock gates gameplay. Hub mode creates no peer connections, uses only Hub transport, handles explicit roster removal, reports all remaining teammates tied, finishes on time-up, and stops traffic and callbacks on end. Root owns stopped sound and UI restrictions.

Primary API references inspected: [W3C WebRTC Recommendation](https://www.w3.org/TR/webrtc/) and [official peer-connection guide](https://webrtc.org/getting-started/peer-connections). Local two-context real WebRTC and the vendored harness matrix are automated; actual WAN/NAT combinations and physical two-device play remain unknown until performed.

## Evidence so far

- `tests/network.mjs`: 38 assertions pass, including codec roundtrip, malformed/version/nonce rejection, event deduplication/acknowledgement, heartbeat release, packet byte/rate bounds, chunk assembly, tied results, dedicated-server seat/clock lifecycle, removal and time-up/end behavior.
- `tests/network_browser.py`: 10 assertions pass using two real Chromium contexts loaded from `file://`, completing real LAN ICE offer/answer over the production adapter, replicating fixture state, preserving a sub-send-interval press exactly once and removing a departing guest. The fixture isolates transport; it is not evidence of completing production combat.
- `tests/hub_browser.py`: **97 checks pass** against the packed final HTML through the unchanged six-case Hub harness: two players, 150 ms latency / 50 ms jitter / 5% loss, adverse host departure, dedicated authority with no local seat, one player, and explicit guest removal. The dedicated authority advances with exactly the real two roster seats. Full evidence is in `hub-test-report.json`.
- `tests/network_game_browser.py`: **11 checks pass** against the packed game loaded from `file://` in two real Chromium contexts with independent standard-map DualSense stubs. Both rangers walk the authored Chalk Burrows, collect one contested supply without duplication, the guest's 40 ms fire press creates one shot/wound/ammunition debit and one shared rat defeat, and both acquire the axe with matching party state. Guest departure removes their actor while the host continues its current expedition solo. A fresh real handshake then rejoins that same expedition without resetting its clock, ammunition, tools or enemy wounds, and places the new ranger at a protected valid nearby anchor. A second departure again continues solo. No simulation state is teleported, gifted, killed or otherwise rewritten. Evidence is in `network-game-report.json`.


### Reconnection regression found and repaired

A focused asynchronous-codec test reproduced one high-severity transport defect: a decode begun under an old peer nonce could complete after a fresh handshake reset the connection state, then apply the prior expedition snapshot. A matching encode race could enqueue an old state using the new connection envelope. An old high sequence number could suppress subsequent fresh snapshots. Both encode and decode now capture their starting nonce and discard their result if it changed while awaiting the codec. Two regressions cover this boundary; the protocol suite now passes 38 assertions. The authority’s inventory/progression was not mutated by the decode race.

A separate browser director failure after restoring the smaller authored creature radii was test behavior: sprinting while firing from a delayed guest view led to repeated poor shots. The director now stops both rangers and deliberately draws from a stationary host position for later guards; its initial 40 ms guest shot still verifies the remote discrete-action path exactly once. No gameplay rule or authored difficulty was relaxed.
