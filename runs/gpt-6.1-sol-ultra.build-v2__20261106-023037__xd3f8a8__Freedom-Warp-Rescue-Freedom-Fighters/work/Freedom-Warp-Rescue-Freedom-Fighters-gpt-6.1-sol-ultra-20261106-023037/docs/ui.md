# Frontend and input contract

`FWR.Input(game, options)` extends the engine's actual `E.Input` instances. No simulation rule reads DOM events. Native action mapping, radial dead zones, labels, key/controller rebinding, Shell focus navigation, and clear-on-focus-loss remain the base. Custom touch disables the native drawn stick and implements two pointer-ID-tracked invisible contacts. Native tick wrappers observe intentional controller changes before Shell handles menus, and consume an attract-exit action until release.

Options: `getWorld()`, `screenToWorld(cssClientX, cssClientY)`, `onActivity(family,event)` (return true to consume), `onPause()`, `onSeatsChange(ids,swapped)`, `onJoin(joined,message)`, `settings()` returning current preference object, `isBlocked()`, `isHub` (boolean or getter). `poll(dt)` returns `{ 'local-1': intent, 'local-2': intent }`. An intent is `{mx,my,ax,ay,fire,burst}`. Fields are finite, radial movement is normalized, neutral aim is zero for the simulation to retain its prior bearing. `seats`, `coOp`, `swapped`, `family`, `join(padIndex?)`, `leave()`, `swap()`, `clear()`, `label(action,seatIndex?)`, `dispose()` are public.

Only a deliberate join or Options on an unclaimed second pad creates the second seat. Keyboard + one pad is supported by assigning that pad to the navigator and disabling the pilot's pad capture. Two-pad use retains the first pad for the pilot. Disconnection clears latches and restores full solo authority. Joining is unavailable inside Hub because the Hub roster owns roles. Touch auto-aim rejects any enemy ray intersecting a captive crystal and never alters collision/rescue rules. Right-thumb double tap can request hyperspace without a contextual eligibility gate; a temporary contact WARP button is also available. Pointerup, pointercancel, blur and resize clear contacts.

`FWR.UI(E,game,options)` owns an `E.Shell` with TV scaling, standard menu disabled, and a custom native-style theme. Its options are `input`, `store`, `onAction(name,value)`, `getWorld()`, `getConfig()`, `setConfig(key,value)`, `getDevState()`, `report`, `isHub`. Methods: `showTitle()`, `showPause()`, `showResults(world)`, `showFailure(world)`, `showSettings()`, `showControls()`, `showCoop()`, `showAbout(page)`, `showDev(group?)`, `hide()`, `update(dt)`, `toast(title,text,seconds)`, `dispose()`; `screen` reads the current Shell screen. Scene `pausable:false` avoids duplicate native pause behavior; root pauses simulation while still updating devices and UI. Native Shell Options/close paths are reconciled back to the root pause state. Results/failure close paths return to title in standalone. About updates replace the same Shell stack frame, allowing one Back to leave after arbitrary page changes.

Action names: `play`, `evasion`, `resumeCheckpoint`, `pause`, `resume`, `retry`, `restart`, `title`, `join`, `leave`, `swap`, `settingsChanged`, `uiSound`, `devReset`, `devSector`, `devSeed`, `devRefill`, `devSpawn`, `devStep`, `devInvulnerable`, `devOverlay`, `devTimeScale`. Mutating controls are disabled during Hub sessions. Balance ranges derive from `FWR.SCHEMA`, and current values are synchronized when opening a balance page. Root handles all world mutations and record eligibility.

`FWR.Store(storage?)` uses version 2 at `freedom-warp-rescue.v2`. Preferences: master=.75, music=.10, effects=.8, voice=.7, glyphs='playstation', reducedMotion=false, touchAssist=true. It validates/clamps loaded settings and ignores malformed or old saves. Checkpoints require world version 1, numeric seed, valid sector 0..4 and operation/evasion mode. Public `settings`/`getSettings()`, `setSettings(partial)`, `best(mode)`, `record(mode,score,eligible=true)`, `getCheckpoint()`, `saveCheckpoint(data,eligible=true)`, `clearCheckpoint()`, `available`, `warning`. Checkpoint getters deep-copy values. Debug/attract/Hub writers must use eligibility false or not be called; the root owns this decision. Denied storage keeps usable in-memory state.

Validation: `tests/frontend.mjs` exports `frontendTests()` result records for the quiet unified runner. It checks preference defaults/persistence, storage failures, record exclusion, semantic normalized movement, effective rebinding, pad solo, two-pad and keyboard+pad joins, disconnect recovery, attract exit consumption, crystal-safe targeting, all native Shell screens, closeAll pause regression, and native engine errors. Browser touch and menu visuals are checked on the integrated final HTML.
