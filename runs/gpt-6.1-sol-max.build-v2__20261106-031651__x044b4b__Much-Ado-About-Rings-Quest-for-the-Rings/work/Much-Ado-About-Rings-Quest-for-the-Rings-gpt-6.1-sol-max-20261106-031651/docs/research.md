# Research and provenance

Historical evidence and the new adaptation are distinct. No original illustrations or screenshots are included in the playable file.

The original [manual transcript](https://odyssey2.info/library/manuals/us_questfortherings/quest-for-the-rings.txt) establishes a physical route board joined to simultaneous two-hero labyrinth play; ten rings; turn pressure; four distinct heroes; four environment families; and a human or computer Ringmaster. The scanned [manual and packaging](https://odyssey2.info/library/library_view.php?i=53) were inspected locally, including the gold cover, illustrated hero page and dungeon illustration with an actual gameplay screen. The local research PDF contains 36 pages. These observations informed warm gold treasure, dark masonry, readable hero silhouettes and ominous original prose.

Historical mechanics retained as relationships: Warrior kills lesser foes; Wizard temporarily neutralizes; Phantom passes interior stone/crystal but cannot cross lava; Changeling diverts attention without contact immunity; a recovered ring benefits the party. Spider/flying Nightmares and dragons are impervious to ordinary killing. Rings link tactical room play to strategic route changes. The original manual describes lightning/trumpet celebration. Exact original audio timbres and continuous background music are unknown.

New designs: four rings rather than ten, carry-and-extract objectives, a full solo companion, capped Dread, authored possession projections rather than stolen controls, safe checkpoint recovery, optional immediate-benefit caches, a four-station dragon binding, touch assistance and accessibility settings. All dialogue, music, effects, voices and distinctive visual assets were authored for this adaptation.

Engine evidence: [handoff README](https://github.com/michaelcrosato/my-3d2dge/blob/8ecc2f62353761187bdfe226f327b7ea5d2eb691/dist/handoff/README.md), full API card, asset manual and adventure kit at **8ecc2f62353761187bdfe226f327b7ea5d2eb691**, version **0.89.1**. The full `my-3d2dge.js` is bundled once. The small agent edition and external 3D renderer are not used. TileMap/Body movement, native Attack timelines, Humanoid animation, materials/shapes, pixel drawing, native Shell menus/settings/rebinding/local joining and native audio synthesis are used. Seven bespoke shapes were inspected with the supplied native asset-sheet tool. Generic props come from the engine’s code library. Engine source is unmodified; game-owned registries and adapters extend it. The engine’s MIT license is included in the HTML and vendor folder.

Protocol evidence: [AI Hub Session Protocol v1](https://github.com/michaelcrosato/ai-hub/blob/35a1047f2067b2af3de3943f0fe452f39105d869/lib/hub/README.md), client, harness, bridge and round coordinator at **35a1047f2067b2af3de3943f0fe452f39105d869**, client **1.4.0**. The unchanged session script is the first head script immediately after the charset. The game uses shared-world authority, validated sender ownership, 10 Hz input/snapshot traffic, reliable scene state, sequence/epoch validation, stale input neutralization, an ownerless server host, time-up/end/departure handlers and one cooperative finish. Presentation interpolation is separate from authoritative state. No sockets, broker, chat or standalone online transport is added. A separate Hub license was not found in the pinned root; its license is unknown.

SHA-256 checksums for the vendored runtime files are generated in `dependencies.json`. No current-main API assumptions are needed: the implementation uses the pinned supplied baseline.
