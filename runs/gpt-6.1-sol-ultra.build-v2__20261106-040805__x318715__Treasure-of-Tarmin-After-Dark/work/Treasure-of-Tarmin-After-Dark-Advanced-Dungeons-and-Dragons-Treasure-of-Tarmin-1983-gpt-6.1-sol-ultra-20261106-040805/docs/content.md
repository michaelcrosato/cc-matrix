# Content and deterministic rules

The authored campaign lives in `src/content.js`. Editing maps, enemies, items, prose, loot, doors, or gates requires no combat-code changes. `CONTENT` is the import/export envelope: `{version:1,items,enemies,floors}`. The in-game developer panel previews and imports this same object. Rebuild with `npm run build` to embed edited data in the single HTML.

Each floor contains a rectangular `rows` array (`#` wall, `.` floor), a named start tile and quarter-turn heading (`0` north, `1` east, `2` south, `3` west), an explicit ladder tile on the first two floors, and arrays of enemies, loot, doors, and features. Every entity has a unique stable string ID and integer `x,y` tile coordinates. Features are `mural`, `gate`, `secret`, `trap`, `camp`, `cache`, or `treasure`. Gates have a destination and explicit strength deltas. Loot references an item definition; food and arrows use an integer `amount`; keys use a permanent shared keyring.

The Upper Vault introduces the Marrow watchman, Cinder rune, Sigilback scorpion, brass key/door, counters, six-slot pack, and one-way descent. The Spirit Passages place the oath ring, permanent training, Doorless sentinel, Bellows ogre, wall-sight, a safely disarmable wired coffer, an Ember gate, and a sighing secret wall. The Guardian Approach contains the alternating Veil, a final ogre, guaranteed preparation supplies and baseline equipment, and the three-seal Horned Warden. Its treasure remains a separate interaction after the guardian falls.

`validateContent()` returns an array of error strings; an empty array means valid. It checks malformed schemas, map shape, stable IDs, item/enemy references and statistics, legal spawns, collisions, finite counters, reachability, reachable key acquisition before locked-door traversal, floor-entry food, required tutorial rune, treasure, and every one-way gate's destination, escape tile, recovery supplies, and path to the next objective without relying on another transfer. Secret walls are assumed discoverable/openable in reachability proofs; they never hold a required key. The validator also runs before importing content, so a failed import leaves the current campaign intact.

`src/core.js` owns every authoritative change. It has no DOM, renderer, audio, storage, or transport dependency. The mutable run is serializable, with stable entity/event IDs, a seeded RNG, integer logical tiles, explicit strengths, inventory, progression flags, and a monotonic simulation clock. The renderer receives bounded event history and cannot apply combat damage. `snapshot` and `restore` preserve the floor arrays and re-establish their active-floor aliases; restoration rejects corrupt strengths, counters, positions, items, entities, and incompatible versions.

Commands are `move`, `turn`, `attack`, `guard`, `equip`, `swap`, `use`, `interact`, `pickup`, `drop`, `rest`, `retreat`, `descend`, `revive`, `handoff`, `continueBoss`, and `retry`. An attack without `channel` uses the right-hand implement. An explicit `channel:'war'|'spirit'` chooses the learned three-point fallback. `attackPreview` gives the same range, power, reduction, final damage, and cost used at resolution. Armor can reduce outgoing damage to zero, which is shown honestly. Spiritual attacks never consume the player's Spirit survival pool.

One encounter owns one numbered round and a fixed visible enemy intention. Committing the first co-op action starts one deadline; subsequent or duplicate plans cannot extend it. Friendly actions resolve in stable player-ID order and are revalidated before consuming anything. An invalidated intention guards without consuming the planned item. Surviving enemy actions follow; slain enemies cannot deliver their scheduled blows. The ogre's heavy attack tracks its announced tile, so moving can evade it. Guard reduces the next matching hit by four. The boss preserves all damage between seals and pauses for preparation after each phase change. A treasure claim, not boss death, ends the expedition.

Rations are confirmed exact previews, clamped to both maxima, and never spent at full strength. Either strength at zero downs a player. Nearby revival consumes exactly one ration and restores each pool to at least 30%, preserving any higher remaining pool. Downed allies travel during descent without being revived or blocking readiness. Departure deposits transferable personal gear and counters at a reachable teammate tile while retaining shared keys. Solo floor-entry checkpoints restore viable original supplies and entities; network runs do not create solo checkpoints.

`tools/test-core.mjs` exports `verifyCore()`, `fullPlaythrough()`, and `scriptedRoute()`. The latter returns production commands suitable for replay against the delivered browser bundle. The complete normal-rules route uses 134 commands, 61 moves, and 27 combat rounds, defeats every ordinary role and all three guardian phases, exercises both damage channels, armor/ring, books, rest, trap, secret, gate, key/door, and descent, and explicitly collects the treasure. Its 100 ms command timestamps are deterministic test time, not a measured human play duration.

Balance overrides and developer operations change this same state and mark the run modified. Scored/Hub sessions reject them. The default tuning object is canonical; reset uses it rather than guessed values. The tools expose floor/encounter jumps, supplies, item creation, invulnerability, map reveal, and clock stepping without replacing the production command system.
