# Procedural audio

`src/audio.js` provides original native-synth cues and five native music arrangements (title, mission, command craft, victory, defeat). The recurring D-minor beacon melody has a quiet bass orbit and sparse percussion; the command arrangement uses the same motif with a quicker pulse. All notes and noise are generated by code. No sound files are loaded.

The shield-ready cue is a rising sine/triangle triad. Gunship warnings use three low, held square pulses. Cannon is a short descending pulse with a bass thump; shield collapse, damage, fusion and missile launches have separate envelopes. Each chain step raises the feedback pitch by a semitone, capped after seven increments. A per-cue rate limit controls simultaneous cascades, while event IDs prevent duplicate effects from repeated snapshots.

Short radio gibberish uses deterministic syllable rhythms and three oscillator bands per syllable, routed into the native voice bus. Sector, rescue, boss-phase and result events trigger it; readable subtitles belong to the root presentation. No recorded speech or intelligible voice synthesis is used.

## Integration

Construct `createAudio(game)` after the native game; call `unlock()` only on a user gesture or meaningful controller input. Setting a scene and submitting events while locked does not initialize Web Audio. Configure the native setting default with `menu.settings: [{key:'music',value:0.1}]` when creating the game; stored player choices remain intact. Menus with native `E.Menu` default `sound:true`, so use `sound:false` if strict pre-gesture context creation must be avoided, and send focus/confirm events through this driver.

Call `setScene('title'|'mission'|'boss'|'victory'|'defeat')` on flow transitions, `event(record)` once per simulation event, `update(dt)` on the application clock, and `setPaused(true)` / `setPaused(false)` on pause changes. `stop()` cancels all effect handles and scheduled gibberish, stops native music, and applies native master mute immediately so already-scheduled music/crossfades are silent. It does not change saved settings. It refuses subsequent events until an explicit `setScene()` or `unlock()` rearms it and restores the player's Sound choice. On Hub end the app must keep it stopped and must not issue another scene selection. Audio never advances or freezes authority.

## Verification

`await verifyAudio()` returns named checks, with no console output, for root's one-command browser test coordinator. It renders every cue and all five scores through the actual native synth into `OfflineAudioContext`, checks finite/nonzero/bounded samples, checks ready/warning differences and generated voice, proves native master mute and source-stop tails, measures the music bus ratio at 0.10, and checks locked behavior and default levels. These are automated signal checks. Subjective listening quality is unknown because there is no listener in the specified environment.

No engine source modifications were needed. The offline harness deliberately injects a context and uses native internal `_voice` and `_note` methods to render the same cue data; those private methods are isolated to the test helper, not application runtime.
